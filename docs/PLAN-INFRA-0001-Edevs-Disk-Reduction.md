# Уменьшение root-диска edevs: 100 → 25 ГБ

Дата: 2026-10-03, Europe/Moscow. План подготовки и замены root-диска согласован владельцем командой «делай».

## Состояние

Подготовка и замена root-диска через VK Cloud выполнены. После сообщения владельца «запустил» проведена проверка 2026-10-03.
Исходная ВМ `edevs`, IP `84.23.55.108`, работает с новым диском **25 ГБ**; SSH host key и статическая сеть сохранены.
Временная ВМ `ubuntu_STD2-1-1_25GB`, IP `161.104.107.170`, выключена после подготовки диска.
Обе ВМ находятся в зоне Москва (ME1); временный диск — 25 ГБ.
Сайты, реальные Markmello API и QR proxy проверены локально и извне по настоящему DNS. Результаты: `REPORT-INFRA-0001-Edevs-Disk-Preparation.md`.
Состояние сохранённых дисков/снимков и их тарификацию нужно проверить в кабинете; удаление старых ресурсов не выполнялось агентом.

## Согласованный перенос

1. Подготовить Ubuntu 24.04, Docker, Nginx, Certbot и 2 ГБ swap на временной ВМ.
2. Перенести `/var/www/edevs.tech`, `/var/www/ermolaev.tech`, `/var/www/games.ermolaev.tech`, `/var/www/skaro.dev`.
3. Сохранить `/opt/markmello-website`, действующий image и named volume `markmello-website_markmello-data` без пересборки.
4. Сохранить Nginx, TLS/ACME-конфигурацию и существующие SSH/CI-доступы. Оставить QR proxy на `138.124.109.186`.
5. Проверить настоящие сайты и API, перезагрузку и автозапуск на временной ВМ.
6. Подготовить диск к загрузке в исходной ВМ: прежний статический IP, MAC, gateway, DNS, hostname и SSH host keys.
7. Владелец заменяет root-диск через кабинет VK Cloud. Исходная ВМ и её сетевое подключение сохраняются.

QuotaRadar runtime, PostgreSQL/Redis volumes, weather-bot, старые images и build cache на новый диск не переносились.
Прежний диск 100 ГБ предназначен для отката; удаление не разрешено этим планом.

## Почему используется клон подготовленного диска

VK Cloud не позволяет уменьшить существующий диск. Восстановление снимка диска 100 ГБ не даёт диск 25 ГБ.
Root-диск временной ВМ нельзя отсоединить обычной операцией отключения data-диска.
Для замены выбирается отдельный, не подключённый к ВМ клон уже подготовленного диска 25 ГБ.
Временная ВМ остаётся выключенной, чтобы клон получился из завершённой файловой системы.

## Выполненная последовательность переключения в VK Cloud

1. На исходной ВМ `edevs` создать страховочный снимок прежнего диска **100 ГБ** и дождаться завершения.
2. У выключенной временной ВМ открыть вкладку «Диски» и выбрать «Клонировать диск» для **25 ГБ**.
3. Для клона оставить размер **25 ГБ**, зону **ME1**, тип сетевого HDD; убедиться, что диск загрузочный.
   Рекомендуемое имя: `edevs-root25-ready-20261003`.
4. Дождаться готовности клона. Он должен быть не подключён к инстансу.
5. Только после готовности клона остановить исходную ВМ **edevs / 84.23.55.108**.
6. В её вкладке «Диски» у прежнего диска выбрать «Заменить root-диск», указать подготовленный **клон 25 ГБ**.
   Прежний диск и снимок не удалять. Если интерфейс предлагает удаление прежнего диска, его не выбирать.
7. Запустить исходную ВМ `edevs` и сообщить агенту о запуске для проверки SSH, IP, файловой системы, сайтов, API и QR proxy.

DNS менять не требуется: исходная ВМ и её сетевой порт остаются прежними.
Временную ВМ нельзя повторно запускать в текущем состоянии: её диск подготовлен под сеть и SSH-идентичность исходной ВМ.
Прямой доступ к `161.104.107.170` после подготовки не ожидается.

## Откат

Если подготовленный диск не загрузится или сеть не поднимется, остановить `edevs` и вернуть прежний диск **100 ГБ** через ту же операцию замены root-диска.
Исходный Markmello при подготовке не останавливался; при возврате прежнего диска он должен запуститься с сохранённым deployment.
При необходимости восстановления исходного диска использовать страховочный снимок.

Удаление диска 100 ГБ, снимка, временной ВМ и её диска — отдельный этап после проверки результата и указания владельца.
Остановленные ВМ, отсоединённые диски и снимки могут продолжать тарифицироваться: подготовка сама по себе ещё не уменьшает общую стоимость хранения.
