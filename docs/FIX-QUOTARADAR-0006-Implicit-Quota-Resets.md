# Короткие объявления массового сброса квот

Исправление согласовано владельцем 11 октября 2026 после ошибочной классификации
поста `@thsottiaux` `2109045392684032299`:

> Global reset by EOD. May the tokens do good things for you.

Первоначальная LLM-классификация вернула `is_relevant=false`. Четыре повторных
реальных запроса с прежним промптом распознали `quota_reset`. Следовательно,
нельзя считать потерю родительского текста единственной причиной отказа.

## Поведение

- Промпт v4 дополнен правилом для прямых объявлений `@thsottiaux` о глобальном
  сбросе пользовательской квоты с упоминанием tokens без названия Codex.
- Новая миграция наследует сохранённый текст и шаблон v3, сохраняя правки владельца.
  Она переключает только конфигурацию, которая использовала v3. Существующий v4
  и выбранные пользователем другие промпты не перезаписываются.
- Нормализация сохраняет доступный родительский пост `replied_to` из ответа X API.
  Родительский текст отделён от собственного текста публикации; автор и принадлежность
  тому же автору указаны явно. При отсутствии родителя контекст не выдумывается.
- Полный текст, article, URL и alt text родителя сохраняются теми же правилами,
  которые применяются к основному и процитированному посту.
- Отрицательное решение перепроверяется только при сочетании признаков reset,
  массовости и пользовательской квоты в собственном тексте утверждённого источника.
  Слово reset, чужой родительский текст и цитата сами по себе не запускают защиту.
- Вопросы, предположения, явное отрицание, сброс Git, API, настроек, инфраструктуры,
  паролей и собственного аккаунта исключены из этой эвристики.
- Дополнительная оценка выполняется один раз. Она должна подтвердить `quota_reset`
  и пройти существующую проверку провайдера, продукта и текста уведомления.
- При неподтверждённом отказе, ошибке дополнительного запроса или невалидном ответе
  сохраняется существующий статус `failed` с причиной и доступными raw responses.
  Доставка и резервная публикация по ключевому слову для этой ситуации не запускаются.
- При подтверждении сохраняются оба ответа, затем работает обычная идемпотентная доставка.

## Границы

Эвристика выбирает отрицательные ответы для перепроверки, а не устанавливает
релевантность сама. Она не гарантирует правильности всех решений LLM.
Ранее завершённые анализы автоматически не пересматриваются. Дополнительных
запросов X API, интерфейсов, статусов и изменений учётных данных нет.

Проверки используют штатный Docker test-сервис проекта, PostgreSQL и Redis.
Ответы LLM в автоматических тестах изолированы существующим способом через
`unittest.mock`; это тестирование ветвей обработки, а не запуск приложения
поверх подменённого backend и не доказательство точности внешней модели.
