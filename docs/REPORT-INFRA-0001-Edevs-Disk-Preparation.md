# Уменьшение диска edevs: результат 2026-10-03

## Результат

Подготовлен загрузочный диск **25 ГБ** в зоне **ME1** для замены прежнего root-диска 100 ГБ.
Временная ВМ `161.104.107.170` штатно выключена после подготовки под исходную ВМ.
Исходная ВМ `84.23.55.108` не выключалась. В 20:30:34 Europe/Moscow Markmello был healthy, исходные сайты и QR proxy отвечали штатно.
Владелец выполнил замену root-диска и сообщил «запустил». После запуска подтверждены диск **25 ГБ**, прежний IP `84.23.55.108`, SSH host key, сеть и работа приложений.

Первое подключение после замены: **22:39:06 Europe/Moscow**, 2026-10-03.

- `/dev/vda` — **25 ГБ**, корневая ext4 `/dev/vda1` — около 24 ГБ; занято **4,8 ГБ**, свободно **19 ГБ**.
- Прежний IP `84.23.55.108/22`, gateway `84.23.55.254` и SSH host key сохранились. SSH подключился со строгой проверкой known_hosts; `sudo -n` работает.
- Docker, Nginx и `markmello-website.service` active; Markmello healthy, restarts=0, OOM=false, image ID совпадает с исходным.
- Все **81 статический файл** повторно совпали по SHA256; compose, environment file и image reference Markmello совпали побайтно.

Удаление старого диска 100 ГБ, временной ВМ, её диска и снимков агентом не выполнялось. Их наличие и тарификацию нельзя определить из гостевой ОС: нужен кабинет VK Cloud.

## Подготовка к исходной ВМ

На диске сохранены прежние:

- IP `84.23.55.108/22`, MAC `fa:16:3e:7f:79:87`, gateway `84.23.55.254`, DNS `5.61.237.127` и `5.61.237.120`.
- Hostname и SSH host keys исходной ВМ, существующие authorized keys, SSH/CI-конфигурация и Docker-доступ `ubuntu`.
- Nginx vhosts, TLS lineage/ACME account и renewal configuration. Новые сертификаты не выпускались.

Cloud-init отключён маркером `/etc/cloud/cloud-init.disabled`, чтобы на другой ВМ не сбросились подготовленные сеть и SSH-ключи.
После этой подготовки временная ВМ выключена; перезагрузка на прежней временной сети не предусмотрена.
Её исходные сетевые настройки и host keys сохранены в защищённых `helper-netplan` и `helper-ssh` внутри каталога операции.
Загрузка в исходной ВМ с прежним IP после замены root-диска проверена успешно.

## Резервные копии и ограничения

На обеих ВМ: `/opt/edevs-disk-migration/20261003-root25/`, root-only.
В `source/` находятся защищённые архивы сайтов/config/существующих TLS и SSH-настроек, точный image и snapshots Markmello volume. SHA256 проверены при передаче.
На временном диске также сохранены `staged-root/`, `preparation-summary.json`, логи и скрипт `scripts/arm-for-old-vm.sh`.
На исходном диске записано подтверждение успешной подготовки и выключения временной ВМ: `logs/target-arm.receipt`.
Приватный SSH-ключ Windows-владельца на серверы не копировался; временно добавленный ключ удалён из SSH-agent, агент вернулся в исходное пустое состояние.

В перенесённом TLS store есть историческая истёкшая lineage `win.ermolaev.tech`; активного vhost этого сайта не найдено. Сертификат не изменялся.
Предупреждение Nginx о повторном MIME type `text/html` в Skaro существовало на исходной ВМ и не исправлялось в рамках переноса.
Приложения и UI не редактировались, mocks/fixtures/seeds не создавались. Сборка приложений не запускалась: использован действующий image и реальные сервисы.
Изменения других файлов репозитория, существовавшие до этой работы, не затрагивались.
