## Проверки

Штатный Dockerfile/Compose с настоящими PostgreSQL и Redis. Для демонстрации не создавались внешние API-заглушки или временные HTTP-сервисы. Новые тесты проверяют чистые политики, локальное файловое хранилище и изолированную тестовую БД. Существующий suite сохраняет предусмотренные проектом unit-test doubles.

Итоговый полный прогон: **219 тестов прошли**. В том числе:
- конкурентное резервирование недельного бюджета и лимита $2 четырьмя потоками;
- однократность наполнения, окно трёх дней, бесплатное использование имеющегося архива;
- общий дневной предел и выбор лучших событий;
- разделение подтверждённого отказа скачивания URL и неизвестного исхода;
- привязка file_id к боту, стабильность хеша при смене кеша;
- очистка только подтверждённых доставок с сохранением неопределённых;
- регрессия прежнего квотного направления.

Штатная serialized_rollback изоляция TransactionTestCase восстанавливает данные миграций между интеграционными тестами.

Образ собран. Локальные news-миграции 0003/0004 применены. makemigrations --check --dry-run: No changes detected. Django system check: без ошибок. git diff --check проходит. Новые/изменённые Python-файлы не превышают 300 строк, обязанности выделены по модулям.

Команды:

~~~bash

docker compose --profile tools run --rm test python manage.py makemigrations --check --dry-run
docker compose --profile tools run --rm test python manage.py check
~~~

Browser-проверка выполнена на штатном backend http://127.0.0.1:18000/admin/ под ранее созданным news-local-admin. Проверены список настроек, доступное действие «Первично наполнить канал: 3 дня, X до $2» и пустой журнал с фильтрами этапов. Действие не выполнялось. Ранее проверены форма настроек, news/channel-получатель и поле отдельного токена. Штатный Django Admin сохранён без собственного UI и отклонений от baseline.

Локально не запускались платное чтение истории, LLM-редакция настоящих новостей или отправка в Telegram. Код не объявляется проверенным на живых X/LLM/Telegram по результатам локального suite.
