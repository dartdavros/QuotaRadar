# Рекомендации в канале квот QuotaRadar

## Кампания

В существующей Django Admin открыть **Реклама → Рекламные кампании → Добавить**:

1. Выбрать существующий канал квот QuotaRadar.
2. Ввести **Текст рекомендации** с несколькими строками и ссылками.
3. Указать положительное **Количество постов** и включить **Активна**.

Пример ввода:

```text
[5397681122542893003][**Купить Claude со скидкой 5%**](https://t.me/premkaiobot?start=ad_ya_claude_5_2909)
[5208665212483310136][**Купить ChatGPT со скидкой 5%**](https://t.me/premkaiobot?start=ad_ya_chatgpt_5_2909)
```

Поле принимает свободный многострочный текст. Шаблон, число строк, ссылок и
порядок элементов не фиксированы. Поддерживаются Telegram MarkdownV2 и HTML:
жирный текст, курсив, подчёркивание, зачёркивание, спойлеры, вложенное оформление,
ссылки, упоминания через `tg://user?id=...`, код, блоки кода с языком, цитаты,
раскрывающиеся цитаты, кастомные эмодзи и `tg://time` / `<tg-time>`.
HTML автоматически определяется по поддерживаемым тегам вне Markdown-кода;
в одном сообщении используйте один из этих двух синтаксисов.

В Markdown также поддерживаются удобные записи `**жирный текст**`,
`[**Жирная ссылка**](https://...)` и кастомный эмодзи `[ID]` в любом месте текста.
Обычный эмодзи перед `[ID]` не обязателен. По ID приложение запрашивает сведения
через read-only метод `getCustomEmojiStickers`, сохраняет запасной Unicode-эмодзи
в кампании и формирует Telegram entity `custom_emoji`. Запрос не публикует посты.
Если токен или прокси недоступны либо Telegram не вернул эмодзи, форма показывает
причину ошибки; приложение не подставляет выдуманное соответствие ID.
Старая запись `обычный эмодзи[ID]` также сохраняется.

Нативные записи Telegram: `![эмодзи](tg://emoji?id=ID)` в MarkdownV2 или
`<tg-emoji emoji-id="ID">эмодзи</tg-emoji>` в HTML. В них запасной эмодзи уже
присутствует, поэтому запрос для его поиска не нужен. `[ID]` внутри кода или
экранированное `\[ID\]` в Markdown остаётся обычным текстом.
Строка `Рекомендация:` добавляется автоматически. Обычные ссылки поддерживают
HTTP/HTTPS, `tg:`, `mailto:` и `tel:`. Исходная HTML-разметка не вставляется в
страницу: безопасный предпросмотр строится из тех же entities, что и отправка.
Недопустимая вложенность, опасная ссылка или ошибка HTML блокируют сохранение.

Под полем отображается предпросмотр и счётчик. Если для выбранного канала есть
реальная сохранённая доставка, предпросмотр включает её исходный пост; иначе
показывает блок рекомендации. В браузере кастомный эмодзи отображается обычным
эмодзи; его оформление в Telegram зависит от клиента и прав бота.
Если Telegram отклонит кастомный эмодзи, доставка завершается ошибкой: повторной
публикации с обычным эмодзи вместо заданного ID нет. Исходные entities сохраняются,
а рекламное размещение не засчитывается. Приложение не вводит проверку коллекционного username.
Реальная проверка публикации допускается только по отдельной команде владельца:
во втором новостном канале с выбранной новостью из очереди. Пробные публикации
в канале квот запрещены.

Реклама размещается после даты и источника в следующих новых публикациях
выбранного канала. Личные уведомления и канал AI-новостей не включены.
Одновременно активна одна кампания на канал. Новая кампания изначально выключена;
миграции не создают кампании и не запускают отправку.

## Длина

Искусственного лимита рекламы в 200 символов нет. Учитывается платформенный
предел текстового сообщения: основной пост, дата, источник, два переноса строки
и рекомендация вместе должны поместиться в 4096 единиц UTF-16 после разбора
разметки. URL скрытых ссылок и служебная разметка в видимую длину не входят;
новое поле не ограничивает URL прежними 2000 символами. Русская буква обычно
занимает одну единицу, многие эмодзи — две, составные эмодзи — несколько.
Пробелы по краям поля удаляются.

Счётчик показывает длину рекомендации и всего примера поста, если он доступен.
Если выбранный сохранённый пост уже слишком длинный, предпросмотр показывает
предупреждение; рекомендация при этом не обрезается. Во время анализа резервируется
фактическая длина активной рекомендации, включая заголовок и разделитель.
Для нескольких каналов используется наибольшая активная рекомендация.
Ограничение title/message в промпте вычисляется с учётом даты и источника.
Если кампания включена после анализа уже длинного поста, такая доставка
завершается ошибкой подготовки, рекламное размещение не расходуется.

## Учёт и пауза

Старые кампании сохраняют прежний текст и ссылку. При открытии формы они
предлагаются в новом поле разметки; сохранение переводит кампанию на новый
формат. Зафиксированные ранее доставки не меняются.

- **Опубликовано** — только подтверждённые Telegram публикации.
- **Зарезервировано** — ожидающие отправки, отправляемые и неподтверждённые
  размещения. Они занимают доступные места до выяснения результата.
- **Осталось опубликовать** — количество постов минус подтверждённые публикации;
  это значение включает ещё не опубликованные резервы.
- После достижения количества постов кампания автоматически выключается.

Пауза выключает новые назначения. Уже зафиксированная доставка сохраняет свою
рекомендацию при повторе; изменение кампании относится к новым назначениям.
Основной текст, ссылка и её форматирование фиксируются до отправки.
Уменьшить количество ниже опубликованных и зарезервированных нельзя.
Канал сохранённой кампании менять нельзя.

Одновременные отправки блокируют одну запись канала в PostgreSQL перед
резервированием, поэтому не могут занять последнее место дважды.
Подтверждение успеха идемпотентно. Отказ Telegram освобождает резерв.
Для ручного повтора отказавшей доставки снова требуется свободное место в той
же кампании; текст повтора остаётся прежним. Срок свежести события остаётся
30 минут. Доставки без рекламы продолжают использовать существующую политику
повторов; их текст также фиксируется перед первой отправкой.

## Неизвестный результат

429 допускает повтор той же зафиксированной доставки. При таймауте, 5xx,
некорректной квитанции или восстановлении прерванной отправки с рекомендацией
автоматического повтора нет. В журнале доставки появляется **Требуется проверка
канала**, резерв сохраняется; ошибка видна в существующем мониторинге Telegram.

В **Рекламных размещениях** открыть запись с этим статусом, проверить настоящий
канал и записать **Результат проверки канала**. Если пост найден, указать его
**Telegram message ID найденного поста**. Затем в списке выполнить действие:

- **Канал проверен: пост опубликован** — засчитывает размещение один раз.
- **Канал проверен: пост отсутствует** — освобождает резерв и помечает доставку
  ошибочной. При необходимости её можно вернуть в очередь существующим
  действием в **Доставках Telegram**, с учётом свободных мест и свежести события.

Отправляемую прямо сейчас запись подтверждать вручную нельзя. Прерванная
попытка становится неподтверждённой при штатном восстановлении доставки.
